## Что проверено автоматически

`npm run build` для конфигурации основного домена; `node scripts/check-seo.mjs https://triadauc.ru/`; JSON-LD разобран и проверены два филиала и девять услуг; наличие служебных файлов; отсутствие метатега noindex в боевом index.html, правильные canonical/og/sitemap. Негативные проверки отклоняют домен-заглушку, подпапку, деморежим, пустой URL формы и некорректный номер Метрики. Демо отдельно сохраняет noindex и не получает счётчик.

Эти проверки не подтверждают фактический DNS, TLS, HTTP-редиректы, приём заявки, индексацию и позиции нового домена. Они проверяются после размещения. Полевая скорость и лабораторный Lighthouse ещё не измерялись.

## Порядок запуска и проверка результата

1. Подтвердить реальные домены в аккаунте клиента и назначить triadauc.ru основным, если он действительно куплен
2. Разместить один фронтенд в App Platform из проверенного коммита, корень `/`, каталог `dist`; сверить актуальную стоимость до создания приложения. Публичный Git-репозиторий позволяет подключение URL без привязки GitHub OAuth к чужому аккаунту
3. Задать VITE_SITE_URL, VITE_LEAD_URL, VITE_NOINDEX=0, VITE_DEMO=0, VITE_BASE=/, номер счётчика и коды подтверждения прав. VITE_CONTENT_UPDATED — фактическая дата изменения текста
4. Добавить новый домен в разрешённые Origins текущего обработчика, сохранив рабочую отправку и прежние настройки
5. Настроить DNS, бесплатный TLS и постоянные редиректы для альтернативных доменов и www. Не менять почтовые записи без необходимости
6. Проверить HTTP 200 основной страницы, 301/308 альтернативных адресов, настоящий 404 случайного URL, robots/sitemap, отсутствие ссылок на демо, загрузку CSS/JS/шрифтов/изображений
7. Проверить форму с перехватом сети. Реальную тестовую заявку в группу отправлять только с отдельного разрешения Андрея
8. Подтвердить права в Яндекс Вебмастере и Google Search Console, отправить sitemap, запросить обход главной; связать Метрику и Вебмастер, указать регион Саратов, проверить цели `lead`, `phone`, `tg`, `tg_channel`, `vk`, `max_group`, `instagram`, `route`, `book_open`, `calc_use`
9. Через 2–3 дня проверить доступность, обход, ошибки; через 1–2 недели — индексацию и выбранный canonical; через 4–6 недель — показы, запросы, страницы входа и заявки. Это план наблюдений, не срок достижения позиций

Резерв: сохранить предыдущий коммит и сборку. До запуска DNS не менялся, возврат локальных SEO-правок не затрагивает работающий GitHub Pages. После старта откатывать версию приложения с сохранением основного домена и аналитики.

## Развитие после запуска

Если нужна заметная органика по нескольким направлениям, следующая работа — отдельные содержательные страницы автозапуска/сигнализаций, шумоизоляции, автозвука и тонировки. Каждая должна объяснять состав и стоимость работ, ограничения, показывать соответствующие реальные кейсы и отвечать на вопросы клиента. Якоря на текущем лендинге не становятся отдельными индексируемыми страницами. Не создавать массовые страницы под марки и районы без самостоятельной пользы и подтверждённого материала.
